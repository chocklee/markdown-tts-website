# M2a 账号与文件库 — 设计文档

> 日期：2026-08-13
> 状态：已确认（待用户最终审阅）
> 范围：M2 子项目 ① —— 账号与认证、文件列表页、自动同步、回收站、存储配额

## 1. 背景与目标

M1 已完成核心朗读闭环（粘贴/上传 → 渲染 → 浏览器语音朗读 + 高亮 + 播放控制，本地存储）。M2 拆为 4 个顺序子项目：① 账号与认证 ② 积分与支付 ③ 云 AI 语音 ④ 文档问答。本文档是第 1 个子项目的设计。

目标：

- 用户可注册、登录，文档自动同步，跨设备可用
- 未登录用户不受影响，本地体验与 M1 完全一致
- 为 M2b 积分支付打好基础（用户账号、配额、鉴权统一）

## 2. 范围

### 2.1 本轮做

- 邮箱注册 + 邮件验证（Resend）
- 登录：邮箱密码 / Google 一键登录（Auth.js v5）
- 忘记密码：邮件重置
- 会话：httpOnly Cookie（JWT）
- 文件列表页「我的文档库」：打开、重命名、删除
- 本地优先 + 后台自动同步
- 回收站（30 天保留，可恢复 / 彻底删除）
- 存储配额（免费 50MB，购买过积分 500MB）

### 2.2 本轮不做（YAGNI）

- 分享链接、团队协作、多设备实时协作（无 CRDT，后写覆盖）
- 邮箱换绑、头像昵称
- Google 以外的第三方登录
- 阅读位置跨设备同步（后续小迭代）
- 复杂账号找回流程（仅基础邮件重置）

## 3. 文档身份：docId

- 每篇文档创建时生成唯一 `docId`（UUID）
- `docId` 相同 = 同一篇；标题只是显示名，重命名不影响身份
- 云端以 `(user_id, doc_id)` 唯一定位
- M1 遗留的本地旧文档没有 `docId`，首次上传时自动生成
- 冲突处理：同一 `docId` 下，以 `updated_at` 后写覆盖

## 4. 账号与认证

### 4.1 注册

1. 填写邮箱 + 密码 → 创建待验证账号 → 发送验证邮件（Resend）
2. 点击邮件链接 → 邮箱验证通过，账号激活
3. 未验证账号不能登录，可重新发送验证邮件
4. 验证链接：一次性、24 小时内有效

### 4.2 登录

- 邮箱密码：验证通过创建会话
- Google 一键登录：OAuth 授权，首次登录自动建号（邮箱视为已验证）
- 同一邮箱已注册过：Google 登录直接绑定到该账号，密码登录不受影响

### 4.3 忘记密码

- 输入邮箱 → 发送重置链接（一次性、24h 有效）→ 设置新密码

### 4.4 会话

- Auth.js v5，JWT 会话，写入 httpOnly Cookie
- 登出即清除 Cookie

### 4.5 未登录用户

- 功能与 M1 完全一致，文档存浏览器本地
- 文件列表页只显示本机文档，顶部提示「登录后跨设备同步」

## 5. 数据模型（Vercel Postgres / Neon）

### users

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid | 主键 |
| email | text unique | 登录邮箱 |
| password_hash | text null | 邮箱密码哈希；纯 Google 注册为 null |
| email_verified_at | timestamptz null | 邮箱验证时间 |
| storage_quota_bytes | bigint | 存储配额；注册默认免费额度；M2b 支付成功后由积分系统更新 |
| created_at / updated_at | timestamptz | 时间戳 |

### documents

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid | 主键 |
| user_id | uuid fk | 归属用户 |
| doc_id | uuid | 文档身份（跨设备唯一） |
| title | text | 显示名，可重命名 |
| content_md | text | Markdown 内容 |
| content_hash | text | 内容哈希（用于判断是否有变化） |
| file_size_bytes | integer | 内容存储占用（配额计算用） |
| deleted_at | timestamptz null | 回收站标记；非空表示已删除 |
| delete_expires_at | timestamptz null | 自动清空时间（创建后 30 天） |
| created_at / updated_at | timestamptz | 时间戳 |

约束与索引：

- 唯一约束 `(user_id, doc_id)`
- 索引：`user_id`、`deleted_at`、`updated_at`

### Auth.js 附加表

`Account`（OAuth 关联）、`VerificationToken`（验证 / 重置链接）由 Auth.js 标准 schema 管理。

## 6. 文件列表页「我的文档库」

- 入口：首页导航「我的文档库」
- 列表项：标题、最后更新时间、大小；操作：打开朗读、重命名、删除
- 排序：最近更新优先
- 未登录：只显示本机文档，顶部登录提示条
- 空状态：引导去粘贴 / 上传第一篇文档
- 回收站入口：列表页右上角；已删除文档显示剩余保留天数，可「恢复」或「彻底删除」

## 7. 同步机制（本地优先 + 后台同步）

### 7.1 原则

- 读写永远先走本地 IndexedDB，秒开、离线可用
- 登录后后台静默同步，失败自动重试
- 同步键：`docId`；冲突按 `updated_at` 后写覆盖

### 7.2 上传（本地 → 云端）

- 触发：登录后、文档保存后（防抖）、手动刷新
- 无 `docId` 的旧文档首传时生成
- 云端同名 `docId` 且云端 `updated_at` 更旧 → 覆盖上传
- 云端 `updated_at` 更新 → 按 7.3 拉回，不覆盖

### 7.3 拉取（云端 → 本地）

- 触发：登录后、进入文件列表页、联网定期
- 云端 `docId` 本地不存在 → 下载到本地
- 本地存在且本地 `updated_at` 更旧 → 以云端版本覆盖本地

### 7.4 删除与回收站

- 删除：本地标记删除 + 云端软删除（写 `deleted_at` / `delete_expires_at`）
- 恢复：清除 `deleted_at`，本地与云端同时恢复
- 彻底删除：本地移除 + 云端硬删除
- 到期清理：Vercel Cron 每日清理 + 打开页面时顺手清理

### 7.5 配额

- 上传前累计云端未删除文档占用，超限则拦截该次上传并提示
- 本地操作不受配额影响

## 8. 安全

- 密码使用 argon2 / bcrypt 强哈希，绝不存明文
- 注册、登录、发邮件接口限流
- 验证 / 重置链接一次性 + 24h 过期
- 密钥与连接串全部走环境变量
- 所有受保护接口统一用 Auth.js 会话鉴权

## 9. 配置中心新增项

| 键 | 默认值 | 说明 |
|---|---|---|
| quota.free_bytes | 50 MB | 免费账号存储配额 |
| quota.paid_bytes | 500 MB | 购买过积分账号的配额 |
| recycle.retention_days | 30 | 回收站保留天数 |
| auth.verification_ttl | 24 h | 验证 / 重置链接有效期 |

说明：配置中心若尚未独立实现，先以常量 / 环境变量承载，M2b 统一收口。

## 10. 验收标准

- 邮箱注册 → 收到验证邮件 → 激活 → 可登录
- 未验证邮箱不能登录
- Google 登录 → 首次自动建号（邮箱已验证）→ 可正常使用
- 忘记密码 → 邮件重置 → 新密码可登录
- 未登录：文件列表只显示本机文档，功能与 M1 一致
- 登录后：本机文档自动出现在云端；换设备登录后同一批文档可见
- 重命名文档不丢失同步
- 删除进回收站，30 天内可恢复；彻底删除后两端都不可见
- 超过配额的上传被拦截并提示
